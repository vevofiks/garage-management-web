# Garage Management System

Garage management & billing web app for Babu Awamir Auto Garage (Qatar) — Next.js (App Router) for both frontend and backend, deployable to Vercel, backed by a PostgreSQL database (Neon recommended).

Full requirements: [`docs/prd.md`](docs/prd.md). Build plan / progress checklist: [`docs/implementation.md`](docs/implementation.md). Original environment walkthrough: [`docs/setup.md`](docs/setup.md) (predates the Postgres/Vercel migration — useful for historical context only).

## Prerequisites

- **Node.js 20+** (`node -v` to check)
- npm (ships with Node)
- A PostgreSQL database — [Neon](https://neon.tech) has a free tier and is what this app is tested against.

## 1. Clone and install

```bash
git clone <repo-url>
cd garage-management-system
npm install
```

## 2. Environment variables

```bash
cp .env.example .env.local
```

| Variable | Required? | What it's for |
|---|---|---|
| `DATABASE_URL` | **Yes** | PostgreSQL connection string. The app bootstraps its schema automatically on first request — there's no separate migration step. |
| `SHADCNIO_TOKEN` | No | Powers the `shadcnio` MCP server (see [Adding shadcn/ui components](#adding-shadcnui-components) below). Every app feature works fully without it. |

## 3. Run the app

```bash
npm run dev
```

Starts the Next.js dev server at http://localhost:3000 with hot reload. First run bootstraps the database schema and seeds a default admin account (`admin` / `admin123` — change this immediately via the Users page). The app redirects to `/login`.

```bash
npm run build   # next build
npm run start   # next start (production server)
npm run lint    # eslint
```

There's no test runner configured yet.

## Deploying to Vercel

1. Push this repo to GitHub (or your Vercel-connected git provider).
2. Import the repo in Vercel and set the `DATABASE_URL` environment variable in the project's settings (same value as your `.env.local`).
3. Deploy — no other configuration is required, Vercel auto-detects the Next.js app.

## 4. Create your first admin account

A default admin account (`admin` / `admin123`) is seeded automatically on first run — change its password immediately via the Users page. To seed an additional admin from the command line instead:

```bash
DATABASE_URL=<your connection string> node scripts/create-admin.js <username> <password>
```

Or use the app's own **Users** page (admin-only) once you're logged in to add `staff` accounts.

## Tech stack

| Layer | Choice |
|---|---|
| Frontend + backend | Next.js 16 (App Router) — UI in `src/app/**/page.tsx`, API in `src/app/api/**/route.ts` |
| Database | PostgreSQL (Neon recommended) via `pg`, schema bootstrapped in `src/lib/db.ts` (no separate migration system — edit the bootstrap SQL block directly) |
| Server state | TanStack Query (`@tanstack/react-query`) — see [`docs/implementation.md`](docs/implementation.md#frontend-architecture-state--data-consistency) for the query-key + invalidation conventions |
| Forms/validation | `react-hook-form` + `zod`, schemas shared between client forms and API route handlers (`src/lib/schemas/*.ts`) |
| UI components | [shadcn/ui](https://ui.shadcn.com) (this project's version builds on `@base-ui/react`, not Radix — see the note below if something you remember about shadcn doesn't match) |
| Auth | Cookie session (`src/lib/auth.ts`), no external auth library |

## ⚠️ This is not the Next.js (or shadcn) you remember

Both Next.js 16 and this project's `shadcn` CLI version are newer than most people's — and any AI assistant's — training data, with real breaking changes. Two that already bit us once (see `docs/implementation.md`'s Phase 1 notes for the full story):

- **`middleware.ts` → `proxy.ts`.** Next.js 16 renamed the file, the export (`proxy`, not `middleware`), and — for a `src/` layout — the required location (`src/proxy.ts`, not the project root). The old convention is silently never invoked; there's no error, no warning, it just doesn't run. If you're adding proxy/middleware logic, start from `src/proxy.ts`.
- **shadcn's `Button` defaults to `nativeButton: true`.** If you compose `<Button render={<Link .../>} />` to make a styled link, pass `nativeButton={false}` or Base UI logs a console error and drops native button semantics.

Before writing code that touches Next.js internals (route handlers, caching, `cookies()`/`headers()`, proxy/middleware, etc.), skim `node_modules/next/dist/docs/` — `AGENTS.md` at the repo root explains why and is auto-regenerated by `next dev`, so don't fight it if it reappears in a diff.

## Adding shadcn/ui components

Preferred path (once set up): ask your AI agent to *"use shadcnio to install `<component-name>`"* — this goes through the `shadcnio` MCP server (already registered in the committed `.mcp.json`), which searches/previews the live registry and asks for approval before writing files.

To unlock it:
1. Get a shadcn.io Pro account token from your shadcn.io account settings.
2. `cp .env.example .env.local` and set `SHADCNIO_TOKEN=<your token>` in `.env.local` (never commit the real token — `.env.local` is gitignored).
3. `set -a; source .env.local; set +a` in your shell (or `export SHADCNIO_TOKEN=...` directly), so the variable is in your shell's environment.
4. Start (or restart) your `claude` session from this directory, and approve the `shadcnio` server when prompted — new project-scoped MCP servers require one-time approval. Check status any time with `claude mcp get shadcnio`.

Fallback, if you haven't set that up yet: `npx shadcn@latest add <component-name>`.

## Project structure

```
src/
  app/
    api/**/route.ts   Backend — all business logic and DB access lives here
    **/page.tsx        Frontend pages (App Router)
    proxy.ts            Auth redirect for unauthenticated requests (see the warning above)
  components/ui/       shadcn/ui components (generated — see "Adding shadcn/ui components")
  hooks/                Shared client hooks (e.g. useAuth, useRequireRole)
  lib/
    db.ts               Postgres connection + schema bootstrap — server-only, never import from a Client Component
    schemas/            zod schemas shared by API routes and client forms
    query-keys.ts        TanStack Query key factory
    api-client.ts         Typed fetch wrapper used by every query/mutation
scripts/create-admin.js  Seeds an additional admin account (see "Create your first admin account" above)
docs/                   PRD, environment setup notes, and the phase-by-phase build plan
```
